# GameStats CS2 — SIS2

SIS2 продолжает проект GameStats CS2 из Checkpoint 1. Программа читает JSON-сессии матчей, проверяет статистику и считает победы, поражения, ничьи, убийства, смерти, помощь и средние значения. Для обработки каждая сессия становится задачей, которую worker pool выполняет в фоне.

## Запуск

Команды выполнять из папки `sis2`:

```bash
go run . examples/session.json
go run . examples/session.json examples/draw.json
go test ./...
go test -race ./...
go vet ./...
```

Go module и формат входных JSON-файлов сохранены от SIS1. Отчёты выводятся в порядке переданных файлов.

## Очередь и workers

В пуле работают 2 постоянные goroutine-worker. Они получают ID задач из буферизованного channel capacity 3 и используют существующий расчёт `AnalyzeMatches`.

```text
JSON -> Create(pending) -> Submit(queued) -> очередь (3)
                                            |       |
                                         worker 1 worker 2
                                            |       |
                                            +-> completed / failed
```

`Submit(id)` возвращает сразу после помещения задачи в очередь, не ожидая расчёта. Когда все три места заняты, он возвращает `ErrQueueFull`; задача остаётся в `pending` и её можно отправить позднее. Повторная отправка queued, processing или завершённой задачи возвращает ошибку.

## Состояния задачи

```text
pending -> queued -> processing -> completed
                               \-> failed
```

При обычном запуске CLI пул останавливается после отправки всех входных файлов: новые задачи больше не принимаются, очередь закрывается, принятые задачи завершаются, main ждёт остановки workers и затем печатает отчёты. Повторный `Stop` безопасен. Если канал очереди заполнится до того, как worker освободит место, CLI вернёт ошибку с именем файла.

## Синхронизация

`TaskStore` защищает map, выдачу ID и переходы состояний с помощью `sync.RWMutex`. `Get` возвращает копию задачи, включая отдельную копию среза матчей. `WorkerPool` использует `sync.Mutex`, чтобы синхронизировать отправку с остановкой и закрыть queue ровно один раз. Workers завершаются через `range` по закрытому каналу, а `sync.WaitGroup` позволяет дождаться всех workers. Длительный расчёт статистики выполняется без удержания mutex хранилища.

Для проверки реального параллелизма тест подменяет только функцию расчёта на синхронизируемую: он ждёт, пока обе worker-goroutine одновременно начнут две разные задачи. Производственный путь использует `AnalyzeMatches`.

Полный ввод, обработка ошибок и правила расчёта описаны в README SIS1 и сохранены в коде SIS2.
